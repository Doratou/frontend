## تصمیم معماری پیش از پیاده‌سازی

- RHF/Zod موجود برای مقدار، touched، validation و خطاهای فیلد؛ password وارد Zustand، URL یا storage نمی‌شود.
- TanStack Query موجود برای session و mutationها؛ mutation بدون retry خودکار و با gcTime=0؛ query key شامل رمز، کد یا شماره نیست.
- Zustand موجود فقط user حداقلی و وضعیت نشست را در حافظه نگه می‌دارد؛ Store تازه ساخته نمی‌شود.
- AuthLayout والد مسیرهای Login/Signup/OTP/Reset است؛ background و برند ثابت می‌مانند. فقط Outlet با AnimatePresence جابه‌جا می‌شود. ارتفاع محتوای متغیر با ResizeObserver و Motion مدیریت می‌شود؛ فرم خروجی inert و از accessibility مخفی می‌شود. فوکوس به عنوان فرم جدید منتقل می‌شود و reduced-motion مسیر بدون حرکت دارد.
- challenge، reset grant و draft شناسه فقط در حافظهٔ همان layout هستند؛ refresh لینک تأیید بدون challenge، recovery روشن نشان می‌دهد. پایان و resend از پاسخ سرور می‌آیند؛ پرشدن OTP به معنی تأیید نیست.
- Motion 14.9.0 قبلاً نصب شده و enter/exit و ارتفاع را پوشش می‌دهد. CSS برای رنگ و state ساده مناسب است؛ React Transition Group برای همین نیاز dependency اضافه می‌خواست و انتخاب نشد. کتابخانهٔ جدیدی لازم نیست.
- API فعلی endpoint احراز هویت ندارد. قرارداد پیشنهادی و adapter جدا ساخته می‌شوند؛ تا فعال‌سازی صریح سرویس، پیام unavailable نشان داده می‌شود و موفقیت ساختگی، token جعلی یا challenge ساختگی تولید نمی‌شود.
- Backend باید session cookie از نوع HttpOnly/Secure/SameSite مناسب، CSRF، محدودیت تلاش/ارسال مجدد، expiry و OAuth state/PKCE را اجرا کند. UI این تضمین‌ها را جایگزین نمی‌کند.

آزمون خودکار و route تست جدید طبق محدودیت قبلی کاربر اضافه نمی‌شود. بررسی دستی، viewportهای درخواستی، فرمت، lint، TypeScript و build انجام می‌شوند؛ موفقیت واقعی SMS/OAuth/session فقط با Backend قابل تأیید است.
